## Findings considered and rejected

- **SECURITY-02** (theoretical mailto: header-injection surface in the mail
  form): confirmed no exploit path exists — there is no URL-parameter or
  hash pre-fill mechanism anywhere in this codebase, so the only person who
  can inject into `from`/`subject`/`message` is the visitor submitting the
  form for themselves. Informational only; not worth a dedicated fix. If
  Plan 002 is being done anyway, stripping `\r`/`\n` from single-line fields
  as defense-in-depth is a free two-line addition — see Plan 002, the
  optional Step 6.
- **5th theme preset / visitor-suggested themes**: `js/theme.js` confirms
  adding a preset is nearly free (one object literal, no other file
  touched), a genuine "adjacent possible" — but there's no evidence anywhere
  (git log, comments, README) of demand for more themes. Not proposed as
  work; recorded so nobody re-discovers this and burns time speccing an
  unrequested feature.
